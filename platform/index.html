Lumora Media Commerce platform & reporting modules

Eight modules turn official Google Ads API responses into consistent, currency-aware reporting for Google Shopping and Search. Each module below lists the exact resource or service it calls, the fields it reads and the structure it produces.

Google Ads API v23REST + JSONGAQLKeywordPlanIdeaService

M1

Account & hierarchy discovery

customerscustomer_client

After authorization, Lumora Media Commerce lists the Google Ads customer IDs the authorizing user can access and reads the manager-account hierarchy. Only descriptive account metadata is stored: customer ID, name, currency and time zone. These four values determine how every later report is labeled, converted and bucketed by day.

M2

Campaign performance reporting

campaignsearchStream

Daily performance per campaign is retrieved with a single streamed GAQL query per account. Cost arrives in micros (one millionth of the account currency) and is converted in M7. The module supports Shopping, Search and Performance Max channel types and keeps the advertising channel type on every row, so Shopping and Search can be reported separately or blended.

Derived metrics

CTR = clicks / impressions · CPC = cost / clicks · ROAS = conversion value / cost · CPA = cost / conversions. Derived values are computed after currency conversion, never averaged across rows.

Comparisons

Every report can be paired with the preceding period of equal length and the same period of the previous year, using the account time zone for day boundaries.

M3

Shopping product-group attribution

shopping_performance_view

Google Shopping results are attributed down to the individual product item and rolled up by brand, product type and custom label. This is how catalogs are evaluated: which product groups carry spend, which convert, and which items accumulate cost without sales.

M4

Search-term & intent analysis

search_term_view

The actual queries that triggered ads are read from the search-term report and classified into intent tiers. Single words and two-word fragments (n-grams) are aggregated across all queries, which reveals patterns that are invisible at the level of individual search terms, such as a recurring "free" or "pattern" modifier that consumes budget without purchases.

Intent tierSignalExample

M5

Keyword idea discovery

generateKeywordIdeas

Keyword ideas expand a short list of category seeds into the related queries people search in a specific market and language. The geo target and language constants come from the market definition in M7, so a German seed is researched in German for Germany and Switzerland and an English seed for the US, UK and Australia.

M6

Historical metrics & CPC benchmarking

generateKeywordHistoricalMetrics

For a defined keyword list, historical metrics return the average monthly search volume, the volume for each of the last twelve months, the competition level and index, the low and high top-of-page bid range and the historical average CPC. Integer values are returned as strings in JSON and are parsed before analysis. The sample values below are illustrative.

M7

Multi-market normalization engine

micros5 currencies

Normalization makes markets comparable without hiding their differences. Each value is kept in the account's native currency and, in addition, expressed in a USD equivalent using a dated reference rate stored with the report. Monthly volumes are converted into a seasonality index (month volume divided by the 12-month mean), which shows when demand peaks independent of market size.

M8

Structured reporting exports

JSONCSV

Every module writes a structured export partitioned by market and date. JSON keeps nested context such as monthly volumes; CSV is UTF-8 encoded with a header row and comma separators for spreadsheet use. Export files are written with file mode 0600 and are not shared with third parties.

Sample rows are illustrative and do not represent real advertiser data.
