Lumora Media Commerce architecture, security & Google API compliance

Lumora Media Commerce is designed around a small, auditable footprint: one OAuth scope, official Google endpoints only, encrypted transport, isolated credentials and a single output, the reporting export. This page documents each control.

Architecture

Two trust zones, one encrypted path between them.

Identity and data stay on Google's infrastructure until a report is requested. Only the requested reporting fields cross into the Lumora Media Commerce environment, over HTTPS, and only structured reports leave the normalization engine.

01OAuth 2.0 authorization with PKCE

Access to Google Ads data is granted exclusively through Google's OAuth 2.0 authorization code flow. Passwords are never seen, requested or stored by Lumora Media Commerce: the authorizing administrator authenticates with Google directly on Google's own consent screen.

The flow uses Proof Key for Code Exchange (PKCE, RFC 7636) with the S256 method, which binds the authorization code to the client instance that started the flow and prevents interception attacks.

  1. A random code_verifier is generated and its SHA-256 hash is sent as code_challenge with code_challenge_method=S256.
  2. The administrator reviews the requested scope on Google's consent screen and approves or declines.
  3. Google returns a one-time authorization code, which is exchanged together with the original code_verifier at https://oauth2.googleapis.com/token.
  4. Google issues a short-lived access token (typically valid for one hour) and a refresh token that remains revocable by the user at any time.

02Least-privilege, single-scope design

Lumora Media Commerce requests exactly one scope: https://www.googleapis.com/auth/adwords. It is the only scope the Google Ads API offers and is required both for GAQL reporting and for Keyword Planner research. No scope for Gmail, Google Drive, Calendar, Contacts, YouTube or any other Google product is requested, and the application cannot access those services.

Within this scope, the reporting and research modules use Google Ads services designed for retrieval: GoogleAdsService search and searchStream for GAQL reports and KeywordPlanIdeaService for keyword ideas and historical metrics.

03Encryption in transit

All traffic between Lumora Media Commerce and Google (the OAuth endpoints and googleads.googleapis.com) is sent over HTTPS with TLS 1.2 or TLS 1.3 and certificate validation enabled. Unencrypted HTTP is never used for API traffic. This website is likewise served exclusively over HTTPS; plain HTTP requests are redirected to HTTPS.

04Credential isolation

OAuth client secrets, refresh tokens and the Google Ads developer token are treated as secrets:

  • Stored on access-controlled systems in files with permission mode 0600, readable only by the service user that runs the reports.
  • Never committed to source control, never embedded in web pages and never stored in a browser.
  • Never written to logs, error messages or reporting exports.
  • Access limited to authorized Lumora Media LLC personnel who need it to operate the service.

Access tokens are kept in memory for their short lifetime and refreshed on demand. If a credential is suspected to be exposed, it is revoked at Google and replaced immediately.

05Data minimization

Each GAQL query selects only the fields needed for the report it produces; there are no full-account dumps. Reporting data consists of advertising statistics and account metadata. Lumora Media Commerce does not process end-customer personal data, payment card details or the content of any other Google service.

Exports are retained only as long as needed for reporting, year-over-year seasonality comparison and statutory record-keeping, and are deleted on verified request within 30 days. Details are set out in the Privacy Policy.

06Instant revocation & deletion

Users stay in control at every point:

  • Revoke access instantly at myaccount.google.com/permissions by removing Lumora Media Commerce. The refresh token stops working immediately and no further data can be retrieved.
  • Revoke programmatically: tokens are also revoked through Google's endpoint https://oauth2.googleapis.com/revoke when a connection is ended by Lumora Media LLC.
  • Request deletion of stored reporting data by email to info@lumoramediacommerce.com. Verified requests are completed within 30 days and confirmed in writing.

07Google API Services User Data Policy & Limited Use

Lumora Media Commerce's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Lumora Media Commerce also complies with the Google APIs Terms of Service and the Google Ads API Terms and Conditions. In practice this means:

  • Google user data is used only to provide and improve the user-facing reporting and research features described on this website.
  • It is not transferred to others except as necessary to provide those features, to comply with applicable law, or as part of a merger or acquisition with prior notice.
  • It is never used to serve, target or retarget advertising, never sold and never used to build user profiles for unrelated purposes.
  • No person reads Google user data unless the user has given explicit consent, it is necessary for security purposes such as investigating abuse, it is required by law, or the data is aggregated and anonymized for internal operations.

08Website security & privacy

This website is a set of static HTML and CSS pages. It contains no forms, no client-side application code, no third-party scripts, no cookies and no tracking pixels, so there is no session to hijack and no visitor data to leak. All pages are publicly accessible without registration.

09Reporting a security concern

Security or privacy concerns, including suspected vulnerabilities, can be reported to info@lumoramediacommerce.com with the subject line "Security". Reports are reviewed promptly by Lumora Media LLC, and good-faith research that respects user privacy is welcome.
